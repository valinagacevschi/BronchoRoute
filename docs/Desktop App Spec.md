# BronchoRoute — Desktop App Spec

BronchoRoute (formerly Lung Navigator) is a local macOS desktop app. It turns a chest CT Archive into an
airway model, a route to a Lesion, and linked anatomical, topology, endoluminal and CT views.
This spec is the build contract for the desktop app. Every decision in it comes from a closed ticket
on the wayfinder map ([GitLab #1](https://git.xelasys.ro/vali/lung-navigator/-/issues/1)); the ticket
holds the reasoning and the rejected alternatives. Vocabulary is defined in `GLOSSARY.md`.

Where this spec conflicts with `docs/Product Requirements Document_ Lung Navigator.md` or
`docs/Workflow and Build Plan.md`, this spec wins for the desktop app (see §13).

## 1. Product frame

- **Platform:** macOS 14+ on Apple Silicon only (PyTorch macOS wheels are arm64-only); 16 GB RAM
  recommended. Windows and Intel Macs are out of scope.
- **Fully local:** segmentation runs on the Mac (MPS/CPU). No cloud processing, no telemetry, no
  upload. The only network calls are the first-run weight download and optional update checks.
- **Research tool:** "Research and education tool. Not a medical device. Not for diagnosis or
  treatment decisions." Shown in About and in every view's footer (no first-launch popup since
  #55). No regulatory (MDR) work is planned; nothing is sold (§11).
- **Patient data:** identifiers (name, ID, birth date, UIDs) are never shown, logged or written.
  Series descriptions and Study dates may appear in the Series picker only. Archive file and folder
  names can contain the patient's name: never log or display them.
- **One Active Case** at a time; processed Cases are kept in the Case Library.

## 2. Architecture ([App architecture and frontend reuse](https://git.xelasys.ro/vali/lung-navigator/-/issues/11), [Desktop shell](https://git.xelasys.ro/vali/lung-navigator/-/issues/2))

- **Shell:** Electron (pinned Chromium). Rejected: Tauri (WKWebView varies with macOS; its sidecar
  model expects a single executable).
- **Sidecar:** a bundled Python built with python-build-standalone + uv (not PyInstaller), running
  the existing FastAPI app (`app/server.py`).
  - Binds `127.0.0.1` on port 0 and prints the chosen port on startup; Electron loads that URL.
  - A per-launch token (generated by Electron, passed to Python) guards every API call.
  - Python exits when its stdin from Electron closes. At startup, kill orphaned job PIDs (PID file)
    and clear `tmp/`. Today a crash leaves segmentation running and later jobs get 409 for up to 45 min.
  - First launch warms the AI stack (~62 s measured once after signing; ~3.4 s later); show it.
- **Jobs:** `app/jobs.py` launches pipeline jobs with `sys.executable`, not `uv run`. One job at a time.
- **Data root:** `~/Library/Application Support/BronchoRoute/`
  - `cases/<local-NNN>/` (Case Library), `models/` (weights), `tmp/` (Archive extraction),
    `settings.json` (initials, update switch), `logs/` (rotated, redacted through
    `jobs.redact_log_line`).
  - Electron passes these paths through the existing env vars (`pipeline/paths.py`).
- **Frontend:** the single-page viewer (`prototype/renderer.template.html` + `ct_panes.js`), plain JS,
  stays the main window. Add three screens: **Import/Library**, **Processing**, **Settings**. Drop the
  `/workflow` `app.html` shell. Bundle the Google fonts (offline).
- **Hidden code:** review/removal/sign-off/versions/walkthrough backend stays behind a feature flag
  with its tests running (§8). The "aeropath" case kind is hidden; the app shows `local-NNN` Cases only.
- **Web deploy:** lung-nav.appcenter.ro is frozen at tag `web-frozen-2026-11-01` (`00462e7`). The
  viewer-only mode stays in the code; no new features target it.
- **Repo layout:** `desktop/` (Electron main, preload, builder config, `desktop/scripts/` packaging);
  Python stays in `app/` and `pipeline/`.
- **Drag-and-drop paths:** `webUtils.getPathForFile` in the preload script; File → Open uses the
  native dialog.

## 3. Import and Series choice ([Archive import and Series picker](https://git.xelasys.ro/vali/lung-navigator/-/issues/15), [Best Series and kernel](https://git.xelasys.ro/vali/lung-navigator/-/issues/4))

- **Input:** zip, folder or DICOMDIR, by drop onto the window or File → Open. Every DICOM file found is
  scanned; everything else (exe, autorun) is ignored.
- **Zip extraction:** into `tmp/` with path-traversal and size (zip-bomb) checks; deleted when
  processing ends or is cancelled. Source DICOM is never kept.
- **Picker:** grouped by Study (date, description). Series rows: description, thickness/spacing,
  kernel (soft/sharp), contrast/non-contrast, z-coverage mm, slice count, status
  **Recommended / Usable / Not usable + reason**. No patient name or ID.
- **Series rule** (replaces `pipeline/import_dicom.py:39`, which matches no Siemens kernel; reference
  implementation `series_rule.py` on branch `research/series-kernel`):
  - Reject: non-CT objects, localizers, derived/report images (e.g. Rayscape), reformats (MPR/MIP,
    non-axial, non-square), < 100 slices, slice step > 1.5 mm, z-coverage < 250 mm, contrast phases
    unless the description says native ("Nativ").
  - Rank: soft kernel first (first kernel value; Siemens number ≥ 50 = sharp), then thinner step,
    longer coverage, more slices.
  - On the test Archive it picks STUDY2 "TAP 1.5 Bf37"; the soft kernel gave +17 % branches and
    +42 % thin terminals over the sharp kernel at identical geometry.
  - GE, Philips and Canon kernels: **Usable**, never Recommended, until real samples are tested.
- **Override:** any Usable Series may be chosen; Not usable cannot. Choice and override reason are
  saved with the Case.
- **Library hit:** a Series already in the Case Library shows "In library" and opens instantly, with
  "Reprocess".
- **Processing view:** steps (reading, segmentation, airway model, graph), elapsed time and estimate
  (~6–7 min), Cancel. Opening another Archive mid-run asks "Cancel current processing?".
- **Failure** (no lungs, empty graph): plain message naming the failed step plus "Try another Series";
  nothing enters the library.

## 4. Segmentation and airway model ([Airway segmentation model and estimated-airway policy](https://git.xelasys.ro/vali/lung-navigator/-/issues/17), [bake-off](https://git.xelasys.ro/vali/lung-navigator/-/issues/16))

- **Model:** TotalSegmentator `lung_vessels` (airways) + `total` (trachea, lobes), always full
  resolution (no `--fast`). Weights Apache-2.0. Block the licensed TotalSegmentator tasks in code.
  Set `send_usage_stats=false` in TotalSegmentator's config.
- **Budget:** ~7 min and ≤ 4 GB RSS per Case on a 16 GB Apple Silicon Mac (measured: 280 s airway
  model, 103 s lobes/trachea).
- **Provenance:** every edge and mask region is `ct`, `interpolated` (≤ 4 mm bridge between CT-seen
  pieces) or `estimated`, plus `manual` for future corrections.
- **Estimated airway** (the one documented exception to "the CT is the anatomical authority"):
  - Extends each CT-seen terminal along the paired pulmonary artery from the same TotalSegmentator
    run, shifted by the tip-to-artery offset (median error 1.5 mm over the first 15 mm on the test
    Case). Reference probe: `artery_follow.py` on branch `research/airway-bakeoff`.
  - Capped at **15 mm** past the last CT-seen tip; fades with distance.
  - Shown as its own layer, on by default, toggleable, dashed, distinct colour.
  - **Never routable**: RouteTarget stays on CT-seen airway; the target gap is measured from CT-seen
    airway; no endoluminal fly into estimated segments; shown in anatomical, topology and CT views only.
  - Topology: dashed, excluded from branch/generation statistics, generation shown as "~N".

## 5. Case Library ([Case cache policy](https://git.xelasys.ro/vali/lung-navigator/-/issues/6))

- Processed Cases are kept; loading a new Archive replaces only the Active Case.
- Key: SHA-256 of the SeriesInstanceUID (`pipeline/import_dicom.py:250`). Each Case records the
  pipeline/model version; an outdated Case opens with "processed with an older version, reprocess?"
  and is never reprocessed automatically.
- Stored per Case: CT volume, masks, airway model, `case.json` (Lesion, Series choice, routes, bridge
  decisions). No source DICOM.
- List: `local-NNN`, Study date, Series description, processed date, size. **No free-text label.**
- No automatic eviction; total size shown; warning above 10 GB.
- "Delete Case" and "Delete all" with confirmation; plain delete.
- No app-level encryption; first-run note recommends FileVault if it is off.

## 6. Lesion, routing and clinical steps ([Marker model](https://git.xelasys.ro/vali/lung-navigator/-/issues/7), [Clinical workflow steps](https://git.xelasys.ro/vali/lung-navigator/-/issues/18))

- **Lesion** (the user's "marker"): exactly one per Case; a point plus a diameter (default 10 mm).
  - Placed by clicking in any CT pane, adjusted by dragging (circle for diameter), confirmed.
  - Fixed in patient RAS. Solid on slices through it; on other slices a faint cross labelled with its
    signed distance ("Lesion +12 mm").
  - Anatomical: translucent labelled sphere. Topology: on the RouteTarget's branch with the target gap
    (before a RouteTarget exists, beside the nearest CT-seen branch). Endoluminal: §7.
  - Record keeps its shape (`ras_mm`, who, when) plus `diameter_mm`; "who" = initials from Settings (3 random capitals generated on first use, editable in Settings; #55).
- **No gating:** the airway shows as soon as processing finishes; the Lesion is optional.
- **RouteTarget:** proposals appear once a Lesion exists: top 3 CT-seen endpoints nearest the Lesion
  (gap, generation, route length), or a click on CT-seen centreline.
- **RouteStart:** automatic at the trachea; no confirmation UI.
- **Interpolated bridges:** v1 has a minimal confirm/reject control per bridge in the CT panes.
  Unconfirmed bridges are never routable; branches reachable only through them show but cannot be
  selected.
- **Review flags** (`small_lobe`, `lobe_without_airways`): viewer warnings, burned into exports; no
  sign-off; nothing blocked.
- **Later (v1.x):** removal of unsupported branches with an evidence note; walkthrough confirmations
  per fork. **Not planned:** sign-off and frozen versions.

## 7. Views

### Endoluminal ([Endoluminal camera rig](https://git.xelasys.ro/vali/lung-navigator/-/issues/8))

Reference prototype: `prototype/proto_endoluminal_rig.html` on branch `prototype/endoluminal-rig`
(`0378814`; never merged). Carry its angle tests into the real tests.

- **No auto-roll.** The image turns with the scope, only when the user rolls it; roll persists along
  the route (parallel-transported frame, `up' = up·cosφ + right·sinφ`).
- **Controls:** ←/→ roll 5° per press (auto-repeat allowed); drag on the scope clock sets the roll;
  ↑/Space advance; pause at forks.
- **Two clocks, bottom left:**
  - **Patient (supine):** 12 = A, 6 = P, 3 = R, 9 = L. Next branch at
    θ_pat = atan2(d·rightA, d·upA), with upA = anterior (0,1,0) projected ⟂ the parent direction and
    rightA = cross(t, upA). A needle shows where the scope's 12 o'clock points on the patient (ψ,
    the signed angle from upA to the screen up about t).
  - **Scope view:** screen-fixed, 12 = top of the scope image. Branch at θ_pat − ψ; "A" at −ψ; hint
    "rotate NN° ↻/↺" (shortest direction, wrapped into (−180°, 180°]); **aligned** within ±15° (green).
- Fork text names both clocks: "Fork N · 12 mm — patient 3 o'clock · scope 12 o'clock".
- When anterior is within the AP-axis degeneracy (|projection| < 0.10), say so.
- **Lesion:** glowing sphere drawn through the airway wall with distance from the tip when in view;
  edge-of-screen arrow with distance when out of view.
- Fix the prototype's cosmetic issues: a fork label under the clocks panel, the anterior tick under the
  side rail, an oversized Lesion glow.

### Realistic fork views ([Realistic forks 1–7](https://git.xelasys.ro/vali/lung-navigator/-/issues/56), #56–#62)

A depth-conditioned image model (`broncho-flow-prototype3-realism-int8.onnx`, 553 MB, from the
`BronchoNavigation` Slicer module) renders one tissue-like still per route fork.

- **Frames:** one per fork on the route (main carina included), camera at `fork.s − 12 mm` (the
  fly-through hold), 120° equidistant fisheye, zero roll. Every child orifice must fall inside the circle.
- **Depth:** the module's `render_depth` and BREA encoder (`brea_geometry_image`), ported unchanged,
  run on the CT airway mask only (`airways.nii.gz`; never Estimated airway). Encoder output must match
  the module's bit for bit on recorded references.
- **Inference:** local CPU, onnxruntime + opencv-python-headless, 12 Euler steps, seed fixed per fork.
  About 5 s per fork on an M5 Pro.
- **Worker:** one background job per Case, started when the RouteTarget is confirmed; nearest fork first;
  frames stream to the viewer as each lands; cancelled and restarted on route change; paused while
  segmentation runs. Cache per Case keyed by route, pose and model SHA-256.
- **Viewer:** during the fork hold the main view fades to the generated fisheye image (R toggles back to
  the schematic view; default on). Roll rotates the image in 2D. The on-route orifice gets the usual
  accent outline and "name + clock" label, projected through the same fisheye camera 8 mm down the
  child centreline. No extra AI badge; the standing "Simulated · CT-derived · research use" footer stays.
- **Model download:** a Settings row "Realistic fork views". The user pastes a key issued by Val (stored
  with Electron `safeStorage`); download resumes, then is checked against a SHA-256 pinned in code. The
  feature stays hidden until the model is verified.
- **Hosting:** `GET https://lung-nav.appcenter.ro/models/<file>` with `Authorization: Bearer <key>`,
  constant-time check against per-user keys in the k8s Secret `lung-nav-model-key`; a separate Ingress
  for `/models/` only (no basic auth, nginx rate limit 5 r/min per IP); Range support; one log line per
  download (key id, IP). The file lives on the lung-nav-data hostPath under `models/` (PV 4 GiB; the bound static PVC stays 2 GiB, hostPath is not enforced).
- **Public snapshot:** code ships; the model and its key never do. Licence for public model release open.
- **Tests:** a stub generator (env var) for UI and Playwright tests; exact-match tests for the depth and
  encoder port.
- **Optional realistic fly-through export:** “Realistic tissue (generated, slow)” generates zero-roll
  keyframes every 2 mm (including the route end), using one shared seed per case. Video travel frames
  crossfade the neighbouring keyframes with signed centre scaling; fork holds retain the realistic
  fork image and labels. Generation is on demand, cached, runs after fork frames, and can be cancelled.
  Failure or cancellation falls back to the normal fly-through. The live view remains fork stills only.

### Topology ([Topology 360° rotation](https://git.xelasys.ro/vali/lung-navigator/-/issues/9))

- Keep the approved radial map (trachea at the centre pointing down at 0°, right lung on the right,
  rings every 5 generations).
- In-plane rotation: Shift-drag; `[` / `]` in 15° steps; corner angle readout with reset to 0°;
  auto-spin (~30°/s). Plain drag still pans, scroll zooms.
- Labels stay upright; a small R/L marker rotates with the map. Rotation resets to 0° on reopen.

### Anatomical and CT panes

Unchanged from the current viewer, plus the Lesion sphere, the Estimated airway layer, bridge
confirm/reject in the CT panes, and review-flag warnings.

## 8. Export ([Image and video export](https://git.xelasys.ro/vali/lung-navigator/-/issues/10))

- **Stills:** "Save image" per view (anatomical, topology, endoluminal); PNG at 2× screen resolution
  as seen, HUD included; toggle to hide the HUD.
- **Video**, MP4 H.264, 1920×1080 at 30 fps (1280×720 option), no GIF:
  1. **Record:** live capture of the current view.
  2. **Route fly-through:** endoluminal, RouteStart → RouteTarget. The scope **auto-aligns** the route
     branch to 12 before each fork (video only; interactive stays manual).
  3. **Anatomical 360° orbit.**
  4. **Topology spin.**
  Types 2–4 are rendered offline frame by frame through the same camera function as interactive
  navigation (PRD EN-07), with progress and Cancel; the app stays usable.
- **Burn-in:** view name, `local-NNN`, export date, Lesion (default on), scale bar (anatomical),
  review flags, footer "Simulated · CT-derived · research use". Never patient name/ID or Study date.
- **Files:** native save dialog; defaults `~/Pictures/BronchoRoute/` and `~/Movies/BronchoRoute/`;
  names like `local-007_endoluminal_20261101-2350.mp4`; no extra metadata.
- One view per export in v1.

## 9. Distribution ([Distribution and installer](https://git.xelasys.ro/vali/lung-navigator/-/issues/12), [Signing and licences](https://git.xelasys.ro/vali/lung-navigator/-/issues/3), [Product name](https://git.xelasys.ro/vali/lung-navigator/-/issues/21))

- **Name:** BronchoRoute (app, DMG, bundle id e.g. `ro.appcenter.bronchoroute`, public repo, data
  folder, wording). "Lung Navigator" was risky: EUTM 012808473 "Lung Protective Navigator" (class 10,
  covers Romania). GitLab `vali/lung-navigator` and the frozen web deploy keep the old name.
- **Repo:** a public GitHub repo started from a clean snapshot with no history; GitLab archived as the
  private record.
- **Licence:** GPL-3.0-or-later (kimimaro and dijkstra3d are GPL-3.0+; every other dependency is
  compatible). Source matching each release tag.
- **Release:** signed, notarized, stapled arm64 DMG plus the electron-updater zip and release notes on
  GitHub Releases (files < 2 GiB).
  - Sign every `.so`/`.dylib` individually, inside out, `--timestamp`, `-o runtime` on executables; no
    `--deep`. Start with no entitlements on the Python child; add `disable-library-validation` /
    `allow-jit` only if a crash proves the need.
  - Built by a local script on Val's Mac using his Developer ID from the Keychain; CI signing later.
- **Weights:** TotalSegmentator weights mirrored as our own GitHub Release assets; first-run download
  (~734 MB) with SHA-256 checks into `models/` (`TOTALSEG_WEIGHTS_PATH`).
- **Updates:** electron-updater checks at launch and asks before downloading; Settings switch to turn
  checks off.
- **Gate:** arm64 + `LSMinimumSystemVersion` 14; first-launch warning below 16 GB RAM.
- **Versioning:** semantic, 0.x until this spec's features are complete.

## 10. Testing

- Playwright against the sidecar on a **temporary state root**, with a guard that fails if real
  `case.json`, `app_state/`, `ts_out/` or `data/` change. Asserted actions are real clicks; the API is
  for setup and read-only checks only.
- One Electron smoke test: launch → import the test Archive → open a Case.
- Angle tests from the endoluminal prototype; Series-rule tests on the test Archive's inventory;
  estimated-airway tests (cap, never routable).
- After any import, verify voxel (0,0,k) maps to the slice's ImagePositionPatient z (first and last
  slice) and that the trachea's world z exceeds the carina's.

## 11. Money and governance ([Monetization](https://git.xelasys.ro/vali/lung-navigator/-/issues/13))

- Free and open source (GPL-3.0+); no paid tier, keys or paywalls.
- Funding from outside the software: research grants and academic collaboration, vendor-neutral
  sponsorship (credited in About), paid training and workshops.
- Adoption is measured by GitHub downloads and stars; no telemetry.

## 12. Build phases (Codex)

Each phase ends with its tests passing, screenshots reviewed, and Val's OK.

| Phase | Scope | Done when |
|---|---|---|
| 0 | Pipeline fixes: skeleton split that drops the left lung, twig root, empty-tree crash ([#14](https://git.xelasys.ro/vali/lung-navigator/-/issues/14)); new Series rule in `import_dicom.py` | Test Archive STUDY2 Bf37 builds a graph matching the fair re-score (≈ 435 branches, gen 14, both lungs); gated series fails cleanly |
| 1 | Electron shell + Python sidecar (python-build-standalone + uv), port 0, token, lifecycle/watchdog, Application Support paths, `sys.executable` jobs, bundled fonts, BronchoRoute naming and bundle id; dev-mode run | App launches unsigned in dev, loads the viewer for an existing Case, survives a force-quit without orphan jobs |
| 2 | Import/Library and Processing screens: zip/folder/DICOMDIR, safe extraction, Series picker, processing progress/cancel/failure, Case Library (list, open, reprocess, delete, size warning, version stamp), FileVault note | Smoke test passes: drop the test Archive → Recommended Series → Case opens; reopening is instant |
| 3 | Lesion (any pane, diameter, all views), no gating, RouteTarget proposals, auto RouteStart, bridge confirm/reject, review-flag warnings, Settings (initials, update switch) | Lesion visible in every view; routes never cross unconfirmed bridges |
| 4 | Endoluminal rig (manual roll, two clocks, Lesion through wall) and topology rotation | Angle tests pass; screenshots match the prototype minus its cosmetic bugs |
| 5 | Estimated airway layer (artery-following, ≤ 15 mm, dashed, never routable) | Tests prove cap and non-routability; layer toggles in all three views |
| 6 | Export: PNG stills, MP4 record, fly-through (auto-align), orbit, topology spin, burn-in rules | Each export type produces a file with correct burn-in and no identifiers |
| 7 | Packaging and release: signing, notarization, weights mirror and first-run download, electron-updater, hardware gate, research wording, GPL licence files, clean public GitHub snapshot | Pre-release checklist below passes; a notarized DMG installs and runs on a clean Mac |

**Pre-release checklist:** notarization + staple verified with `spctl`; first-run weight download
verified against SHA-256; no network calls beyond weights/updates (checked with a proxy); manual
TMview/OSIM search for "BronchoRoute" filtered to Romania; licence and attribution files present;
the public snapshot contains no case data, internal notes or patient names.

## 13. Superseded rules

For the desktop app, this spec replaces:

- **PRD EN-02** (auto-roll to 12 o'clock): manual roll (§7). Auto-align survives only in the
  fly-through video (§8).
- **PRD GR-05** (export refused until review flags are signed off): flags are warnings (§6).
- **Workflow plan step 2 gating** (Lesion before any airway is shown): no gating (§6).
- **Workflow plan step 8** (sign-off and frozen versions): not planned (§6).
- **"Never extend airway"** (CT is the anatomical authority): one exception, Estimated airway (§4).

## 14. Later and out of scope

**Later (not decided):** clinician check of endoluminal behaviour on real scans (incl. anterior
drift without roll); non-Siemens kernel samples; a downloadable demo Case from a public, permissively
licensed chest CT; composite multi-view export; multiple targets or note markers per Case; retiring
lung-nav.appcenter.ro; removal corrections and walkthrough confirmations (v1.x).

**Out of scope:** Windows/Intel; cloud processing; Stefan's reconstruction module (v2); MDR
compliance work; an exclusive bronchoscopy-vendor partnership; open-core paid extras and clinical
licensing; training our own airway model.
